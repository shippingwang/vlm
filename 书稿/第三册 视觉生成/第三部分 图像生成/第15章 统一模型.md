# 第 15 章 统一模型

理解图像要抽语义；生成图像要留纹理。两条任务对表示的需求不完全一样。统一模型试图共用一套骨干，同时做看图说话与按条件出图，并在交错图文，多轮编辑里复用上下文。

本章用 Janus，Show-o，BAGEL 等公开路线当标本，只谈结构分工，不绑死某一版本号。

## 15.1 理解与生成

理解头：图像 → 语义特征 → 文本或标签。生成头：条件 → 视觉 token 或扩散状态 → 图像。若强行共用同一极度压缩的语义向量出图，细节往往不够；若共用像素级网格做理解，又浪费且难对齐语言。

统一的关键是：哪些层共享，何处分叉。

## 15.2 编码与共享骨干

常见拼法：

- 分离编码器：理解走语义塔，生成走 VAE / tokenizer，只在语言侧融合  
- 共享骨干：同一 Transformer 读图文混合序列，不同头出词或出图  
- 混合：浅层共享，深层任务专用  

共享越多，数据与损失越要一起设计，否则一任务吃掉另一任务。

## 15.3 Janus

Janus 明确把理解与生成的视觉编码分开，再在语言模型侧统一。代价是两套视觉前端；收益是各自可以按任务选合适的压缩与分辨率。

## 15.4 Show-o 与 BAGEL

Show-o，BAGEL 一类工作走更紧的共享：同一离散或连续视觉表示上，既做理解又做生成（掩码，自回归或扩散头）。训练混合多种目标与数据格式。

读这类模型时看三点：视觉 token 是否同一套，生成头是扩散还是离散，以及多任务损失如何加权。

## 15.5 交错序列与上下文学习

把图和文排进同一条序列：文 → 图 → 文 → 图。模型按上下文续写，可以少样本模仿版式或风格。这与第 10.4 的检索增强互补：上下文示例在序列里显式给出；检索从库里取，再注入条件通道。

长度一长，视觉 token 占比吃掉上下文窗口，需要压缩或选关键帧。

## 15.6 多轮编辑

统一模型天然适合对话式改图：上一轮的图作为条件，下一轮指令继续改。要盯住的是：历史图以像素，token 还是引用 id 进上下文，以及中间轮误差如何累积。

与第 13 章专用编辑模型比，统一模型胜在接口一致，专模型往往在单一编辑指标上更稳。产品里可以外层对话，内层仍调专用编辑器。

第三部分收束：条件与架构决定文生图主路；编辑与主体决定可控；统一模型把理解接进同一套接口。视频部分会把这里的条件与骨干搬到时间维上。
