# 第 11 章 生成架构

潜变量切成 patch 之后，可以用 Transformer 预测噪声或速度。本章看 DiT 式骨干如何摆位置与条件，以及多模态扩散 Transformer（MMDiT）怎样把文本和图像放进同一套注意力里。SD3，FLUX 是这套架构与流匹配目标的会合点；REPA 则提醒：生成网络内部的表示也可以和对齐目标一起训。

## 11.1 Patch 与位置

把 \(z\in\mathbb{R}^{C\times H'\times W'}\) 划成 patch，展平为 token 序列。位置编码（正弦，可学习，RoPE 等）告诉模型格子在哪。分辨率一变，位置外推或插值策略必须说清楚，否则只换采样分辨率就会花屏。

视频里再加时间维，位置变成时空坐标，见第 17 章。图像这边先把二维位置走稳。

## 11.2 DiT

DiT 用 Transformer 块替代 U-Net 做潜空间扩散骨干。宽度，深度，patch 大小决定容量与 token 数。缩放规律更接近语言模型：加深加宽，配足够数据，往往比继续堆 U-Net 技巧更可预期。

条件注入不走交叉注意力时，常见替代是 adaLN：用 \(t\) 与 \(c\) 的嵌入去调 LayerNorm 的尺度与偏置。

## 11.3 条件归一化

adaLN / adaLN-Zero 把条件变成每块的 \(\gamma,\beta\)（有时还有门控）。时间与文本可先拼成一个条件向量，再投影到各块。相对交叉注意力，参数更省，但文本内部的 token 结构被压成向量，长提示的细节绑定可能变弱。实务上两者常混用。

## 11.4 MMDiT

MMDiT 让文本 token 与图像 token 进入联合注意力（双流或后来的单流融合）。文本不再只是被图像侧查询的外部记忆，而是与图像一起更新。

双流：两套权重，交互靠注意力。单流：拼成一条序列，共享块。SD3，FLUX 的公开叙述都落在这一族附近，细节以各自实现为准。

## 11.5 SD3 与 FLUX

二者共同点：Transformer 骨干 + 流匹配族目标 + 强文本条件。差别在具体块设计，文本编码器组合，训练数据与推理默认步数。

读这类模型时，优先对齐三件事：预测 \(v\) 还是别的，条件是交叉还是联合注意力，采样是哪条 ODE 离散化。架构名词换皮很快，这三件相对稳。

## 11.6 表示对齐与 REPA

生成损失主要管样本是否像数据。REPA 一类工作额外要求中间特征与外部视觉编码器对齐，以改善训练效率或语义结构。

它改的是训练信号，不是推理必须多跑一个编码器。与第 3 章换 VAE 不同：对齐的是去噪网络内部表示，解码器仍可不动。若对齐目标与重建 / 生成目标冲突，需要看验证曲线，而不是只看论文口号。
