# 第 16 章 视频表示

拍摄一座庭院时，相机向右移动，近处的栏杆会比远处的屋檐移动得更快。有人从门前走过，门框的一部分暂时被挡住，随后又露出来。这些变化发生在相邻画面之间，单独查看其中一帧，很难看出完整的运动。

图像模型已经能够压缩轮廓、颜色和纹理。进入视频之后，编码器还需要保存它们随时间变化的方式。如果压缩过程丢掉了人物迈步时的细微差别，后面的生成网络即使训练充分，也只能在受损的表示上工作。因此，在讨论视频生成网络之前，我们先看视频怎样被采样、压缩和组织成序列。

## 16.1 帧率与时间采样

### 帧与时刻

把一段视频写成张量：

\[
X\in\mathbb{R}^{B\times 3\times F\times H\times W}.
\]

其中，\(B\) 是批量大小，\(F\) 是帧数，\(H,W\) 是画面高度和宽度。通道数 3 对应 RGB。代码中也常见 \([B,F,3,H,W]\) 的排列，两种写法都可以，前提是卷积、注意力和编解码接口使用相同约定。本章采用通道在前的排列。

对于恒定帧率 \(r\)，第 \(f\) 帧的采样时刻为

\[
\tau_f=\frac{f}{r},\qquad f=0,1,\ldots,F-1.
\]

这里使用 \(\tau\) 表示视频中的物理时间。扩散或流匹配中的噪声时间记为 \(t\)。生成网络在某个噪声时间 \(t\) 处理的，通常是一整段包含多个 \(\tau_f\) 的视频。

例如，81 帧以 16 fps 采样，首帧与末帧的时间间隔为 \(80/16=5\) 秒。若每帧在播放时都占据 \(1/16\) 秒，完整帧序列的播放时长为 \(81/16=5.0625\) 秒。讨论模型时常把这种规格称为约五秒；制作定长文件时，还需要按输出帧率确定帧数与时间戳。

### 抽帧与动作速度

假设原视频是 30 fps，每隔 3 帧取一帧，新的采样间隔就是 0.1 秒，有效帧率为 10 fps。若仍按 30 fps 播放这些帧，同一个动作会在原来三分之一的时间内完成。

这说明，抽帧步长和输出帧率共同决定画面中的速度。训练时记录的帧率，应当对应模型实际看到的采样时刻。对于可变帧率视频，可以根据时间戳重新采样，不能仅凭文件中的平均帧率推断每两帧之间的时间。

手部挥动、快速转头和旋转物体对时间采样尤其敏感。如果两次采样之间已经发生较大变化，模型看到的可能是突然跳动，甚至是与实际方向相反的旋转。这类现象属于时间混叠。提高输出文件的帧率并不能恢复被抽掉的观测；插帧模型可以估计中间画面，但估计结果仍受输入信息的限制。

曝光时间也会影响训练样本。同样的采样帧率，短曝光保留清楚的边缘，长曝光可能带来运动模糊。一个视频模型学到的运动外观，因而同时受采样间隔与拍摄方式影响。

### 裁剪与画面变化

视频裁剪通常应当在一段片段内保持一致。如果每帧独立随机裁剪，即使相机静止，画面内容也会不断平移，数据中便多出人为制造的运动。

缩放和裁剪还会改变相机内参。假设横纵方向分别缩放 \(s_x,s_y\)，之后从左侧、上侧裁去 \(a,b\) 个像素，则焦距和主点变为

\[
f'_x=s_xf_x,\quad f'_y=s_yf_y,
\qquad
c'_x=s_xc_x-a,\quad c'_y=s_yc_y-b.
\]

如果后续使用深度或相机轨迹作为条件，这些参数也要同步更新。图像和几何条件经过不同的裁剪后，即使各自看起来合理，也已经不再对应同一组像素。

## 16.2 时空压缩

### 从逐帧编码开始

最直接的做法是使用图像编码器，分别处理每一帧：

\[
z_f=E_{\mathrm{img}}(x_f).
\]

若空间压缩倍数为 8，输入 \([B,3,F,H,W]\) 可以变成 \([B,C_z,F,H/8,W/8]\)。画面尺寸减小了，时间长度仍然是 \(F\)。

逐帧编码容易复用图像模型，但编码器无法利用跨帧冗余。更重要的是，细小的纹理变化可能在每帧被压缩成不同的误差。单帧重建都清楚，连起来播放仍可能闪烁。后续生成网络可以学习时间关系，编码器本身却没有受到跨帧信息的帮助。

时空编码器把相邻帧一起处理：

\[
z=E_{\mathrm{vid}}(X)
\in\mathbb{R}^{B\times C_z\times F'\times H'\times W'}.
\]

它既压缩空间，也压缩时间。一个潜变量位置可以包含多个输入帧的信息，因而 \(F'\) 个位置不能直接当作 \(F'\) 张缩小后的图片。

### 压缩后的尺寸

设时间、空间压缩倍数分别为 \(s_t,s_h,s_w\)。对于首帧单独处理、其余帧按时间步长压缩的设计，当输入帧数满足整除要求时，常有

\[
F'=1+\frac{F-1}{s_t},\qquad
H'=\frac{H}{s_h},\qquad W'=\frac{W}{s_w}.
\]

这条公式对应特定的边界与下采样约定。其他编码器可能使用补帧、向上取整或不同的首帧处理方式，读取实际配置时应以实现为准。

以 Wan 2.1 的视频 VAE 为例，时空压缩倍数为 \(4\times8\times8\)，潜变量通道数为 16。[1] 对一个批量大小为 1 的样本，尺寸变化如下：

| 阶段 | 张量尺寸 |
|---|---|
| RGB 视频 | \([1,3,81,480,832]\) |
| VAE 潜变量 | \([1,16,21,60,104]\) |

输入共有 97,044,480 个数，潜变量共有 2,096,640 个数，两者约相差 46.3 倍。这里计算的是张量元素数量。\(4\times8\times8=256\) 描述时空位置的压缩，通道数则由 3 增加到了 16，首帧处理也改变了时间长度，所以实际元素比例会有所不同。

这也不同于视频文件的压缩率。H.264 等视频编码通常把表示进一步量化并编码为比特流，而生成模型的潜变量经常以浮点数保存。比较磁盘大小时，还要计入数值精度、量化与熵编码。

### 压缩会丢掉什么

空间压缩首先影响小字、细线和高频纹理。远处窗格只占几个像素，经过多次下采样后，可能已经不足以区分相邻的线条。

时间压缩则更容易影响短暂事件：手指接触物体的一瞬间、眨眼、快速掠过的细枝，都可能发生在较短的时间范围内。编码器需要把这些变化保存在通道特征中，再由解码器恢复。随着压缩程度增加，这项任务也会变难。

选择压缩率时，需要同时看重建结果和生成成本。较长的潜序列能够保留更多信息，但生成网络每一步都要处理这些信息；较短的潜序列节省计算，却把更多细节恢复交给了解码器。

## 16.3 三维 VAE

### 时间卷积

二维卷积只在高度和宽度方向移动。三维卷积增加时间维，其一个输出可以写为

\[
h_{c,f,u,v}
=
\sum_{c',\delta_f,\delta_u,\delta_v}
W_{c,c',\delta_f,\delta_u,\delta_v}
\,x_{c',f+\delta_f,u+\delta_u,v+\delta_v}.
\]

当时间卷积核长度大于 1 时，当前特征会同时取决于多个输入时刻。以移动的栏杆为例，网络能够把相邻位置的边缘变化作为一个局部时空模式处理。

从二维权重初始化三维网络时，可以把二维卷积核放到某个时间切片，也可以沿时间复制并缩放。不同初始化方式决定了初始网络对相邻帧的依赖程度。加入时间层之后仍需要视频训练，网络才能学习动作、遮挡和时间压缩。

### 后验与重建

视频 VAE 的编码器输出均值和方差：

\[
q_\phi(z\mid X)
=\mathcal{N}\!\left(
\mu_\phi(X),\operatorname{diag}(\sigma_\phi^2(X))
\right).
\]

训练时通过重参数化得到潜变量：

\[
z=\mu_\phi(X)+\sigma_\phi(X)\odot\epsilon,
\qquad \epsilon\sim\mathcal N(0,I),
\]

再由解码器恢复视频：\(\hat X=D_\psi(z)\)。均值和方差与潜变量具有相同的时空网格，因此网络在输出分布参数时通常需要 \(2C_z\) 个通道，抽样后的潜变量仍是 \(C_z\) 个通道。

一个常见的训练目标可以写成

\[
\mathcal L_{\mathrm{VAE}}
=
\lambda_{\mathrm{rec}}\mathcal L_{\mathrm{rec}}
+\beta\,D_{\mathrm{KL}}\!\left(q_\phi(z\mid X)\|\mathcal N(0,I)\right)
+\lambda_{\mathrm{per}}\mathcal L_{\mathrm{per}}
+\lambda_{\mathrm{adv}}\mathcal L_{\mathrm{adv}}.
\]

重建项约束颜色和位置，感知项比较特征，对抗项帮助恢复纹理。KL 项约束编码分布，但它的权重需要与重建要求一起选择。视频生成使用的压缩 VAE，往往更关心能否保存足够的视觉信息，不能仅凭“VAE”这个名称推断其潜变量已经严格服从标准高斯分布。

### 潜变量尺度

生成网络通常不会直接使用编码器输出的原始数值。为了让数据尺度与加噪日程配合，可能先进行

\[
\tilde z=\frac{z-\mu_z}{\sigma_z}.
\]

其中 \(\mu_z,\sigma_z\) 可以是标量，也可以按通道统计。解码前要应用对应的逆变换。部分实现只使用缩放系数，部分实现同时处理均值与方差。

如果换了 VAE，却沿用旧模型的缩放参数，同一个噪声强度就会对应不同的信噪比。结果可能表现为颜色异常、生成不稳定或细节损坏。编码器权重、潜变量统计量和生成模型配置因此需要作为一组相互匹配的参数保存。

## 16.4 因果编码与分块

### 因果卷积

若时间卷积只读取当前及过去的位置，则可以写为

\[
h_f=\sum_{j=0}^{k_t-1}W_j*x_{f-j},
\]

其中 \(*\) 表示空间卷积，\(k_t\) 是时间卷积核长度。序列开头缺少历史位置，需要使用约定的填充方式。

因果结构允许首帧在没有未来观测的情况下编码，也便于逐段处理视频。对图生视频而言，输入照片可以通过同一编码体系成为起始条件。[1][2]

不过，编码器的时间依赖和生成网络的时间依赖需要分别检查。一个使用因果 VAE 的模型，仍然可以在生成时对整段潜变量做双向时空注意力。要判断模型能否逐帧输出，还需要看生成骨干的注意力掩码、采样方式和解码过程。

### 归一化的时间范围

卷积满足因果约束之后，还要检查其他算子有没有读取未来信息。

例如，对 \([B,C,F,H,W]\) 的特征做 GroupNorm 时，常见实现会把组内通道以及 \(F,H,W\) 一起用于统计。即便之前只做了因果卷积，前面时刻的归一化结果也可能因后续帧的数值发生变化。按位置只在通道维归一化，可以避免这种全时间统计。Wan-VAE 使用了相应的 RMSNorm 设计。[1]

这个区别也影响分块推理。如果整段与分块使用了不同范围的统计量，即使卷积边界补齐，输出也可能发生偏差。

### 首帧与缓存

在时间压缩倍数为 4、首帧单独保留的约定下，输入帧数常取 \(4k+1\)。81 帧对应 21 个潜变量位置，单张图片则对应一个位置。

可以把这种长度关系理解为首帧加上后续每四帧产生一个新位置，但各位置的感受野通常会因多层卷积而重叠。因此，潜变量序列中的位置不能看成互不相关的帧组。

分块处理时，每个因果卷积层都要保存自己的历史特征。以时间核长度为 3、步长为 1、膨胀率为 1 的单层卷积为例，当前块需要接上之前两个位置的输入特征。若有下采样，还需要保持步长的对齐关系。

```text
前一块的层内特征 → 保存末尾历史
                         ↓
当前块的层内特征 → 拼接历史 → 因果卷积 → 当前输出
```

只给下一块补几张原始视频帧，未必能重现多层网络整段计算的结果。严格的等价还取决于各层缓存、步长、填充、归一化和注意力范围是否一致。Wan-VAE 的分块实现正是在层内管理这些状态。[1]

空间分块也有类似问题。卷积和注意力在边界处可能缺少邻域信息，因此常采用重叠区域，并对重建结果进行加权合并。如果模型包含跨整幅画面的计算，分块与整图结果通常仍会有差别。

## 16.5 时空 token

### 从潜变量到序列

得到 \([B,C_z,F',H',W']\) 的潜变量后，Video DiT 再把它切成大小为 \(p_t\times p_h\times p_w\) 的块。若各维均可整除，token 数量为

\[
N=
\frac{F'}{p_t}
\frac{H'}{p_h}
\frac{W'}{p_w}.
\]

每块包含 \(C_zp_tp_hp_w\) 个数，经过线性投影成为 \(d\) 维向量：

\[
h_i=W_{\mathrm{in}}\operatorname{vec}(z_i)+b,
\qquad h_i\in\mathbb R^d.
\]

对于前面的 \([1,16,21,60,104]\)，使用 \((p_t,p_h,p_w)=(1,2,2)\)，可以得到

\[
N=21\times30\times52=32760.
\]

每个 patch 的原始宽度为 \(16\times1\times2\times2=64\)。若教学示例取隐层宽度 \(d=1536\)，嵌入后便是 \([1,32760,1536]\)。这里的隐层宽度只用于计算示例，具体模型由配置决定。

下面的函数展示 patch 的排列过程，不包含投影、补齐和位置编码：

```python
# z: [B, C, F, H, W]，这里的 F/H/W 均指潜变量尺寸

def patchify(z, patch_size):
    pt, ph, pw = patch_size
    B, C, F, H, W = z.shape
    assert F % pt == H % ph == W % pw == 0
    x = z.reshape(B, C, F // pt, pt, H // ph, ph, W // pw, pw)
    x = x.permute(0, 2, 4, 6, 1, 3, 5, 7)
    return x.reshape(B, (F // pt) * (H // ph) * (W // pw),
                     C * pt * ph * pw)
```

模型输出后，需要按相同顺序恢复潜变量网格。若输入按“时间—高度—宽度”展开，输出却按另一种顺序恢复，张量尺寸可能完全正确，画面仍会被打乱。

### 序列长度与成本

对于完整自注意力，注意力分数的数量随 \(N^2\) 增长。32760 个 token 的一个注意力头就有约 10.73 亿个分数。若完整保存为 FP16，单个分数矩阵接近 2 GiB，尚未计入其他注意力头、QKV、前馈层和训练梯度。

FlashAttention 等算法通过分块与在线归一化，避免把完整分数矩阵存入显存。它们显著改善访存和显存占用，但完整注意力的配对计算量仍随序列长度的平方增加。

如果高度和宽度都翻倍，而压缩率和 patch 大小不变，token 数会变为四倍，完整注意力的配对数量会变为十六倍。增加时长也会增加序列长度。这就是视频模型必须同时考虑编码压缩、注意力结构与并行方法的原因。

### 位置信息

展开后的序号可以标识一个 token 在序列中的位置，但模型还需要知道它来自哪个时刻、哪个空间坐标。

因此，时空 patch 通常保留 \((f',u',v')\) 三个坐标，用于位置编码。假设时间压缩倍数为 4，同样相差一个潜变量位置，在不同输入帧率下对应的物理时间间隔不同。支持多帧率的模型，需要通过训练分布、帧率条件或坐标设计处理这一差别，单独换一个播放帧率无法改变网络已经生成的运动。

## 16.6 重建与运动损失

### 先检查重建

评估一个视频表示，最直接的起点是

\[
X\longrightarrow E(X)\longrightarrow D(E(X))=\hat X.
\]

这里先去掉生成网络。把原视频与重建视频比较，可以发现编码器和解码器自身的损失。如果原片中的窗格在重建后已经模糊，后续生成结果中的类似问题就不能全部归因于采样器。

PSNR、SSIM 和感知距离可以衡量不同方面的重建误差。[3] 不过，平均分数容易掩盖局部问题：一段以静止背景为主的视频，可能只在手指、眼睛或细小纹理处出现明显损坏。除了全帧指标，还需要观察局部区域与连续播放。

### 时间差分

一种直观的时间损失是比较相邻帧差分：

\[
\mathcal L_{\Delta}
=
\frac{1}{F-1}\sum_{f=0}^{F-2}
\left\|
(\hat x_{f+1}-\hat x_f)-(x_{f+1}-x_f)
\right\|_1.
\]

它要求重建视频在相邻时刻发生相近的变化，能够补充单帧重建项。但像素差分同时受到运动、光照和纹理影响，快速运动也可能带来很大的差分值，因而不能只用这一项判断动作是否合理。这是一个用于解释时间约束的损失形式，具体 VAE 是否采用它，需要查看对应训练方案。

### 运动补偿

如果有从第 \(f\) 帧到第 \(f+1\) 帧的光流，可以在有效可见区域比较对应位置。设 \(\mathcal W(\hat x_f,U_f)\) 表示把前一帧按该光流投影到下一帧，并在重叠位置进行采样，\(M_f\) 表示有效区域，则可构造

\[
\mathcal L_{\mathrm{warp}}
=
\frac{\sum_f
\left\|M_f\odot
\left(\hat x_{f+1}-\mathcal W(\hat x_f,U_f)\right)\right\|_1}
{\sum_f\|M_f\|_1+\varepsilon}.
\]

新露出的区域没有前一帧的观测，需要从约束中排除；反光、透明和大幅光照变化也会破坏简单的颜色一致性。光流本身若有误差，还会把错误对应传给损失。

因此，时间平滑、正确运动与细节保留需要分别观察。把每一帧都变得相同，确实能降低某些时间变化指标，却会丢掉原片中的动作。一个合适的视频表示，应当在保留变化的同时减少编码产生的额外抖动。

完成这些检查后，视频已经从 RGB 帧序列变成具有时间结构的潜变量。接下来的问题是：生成网络怎样同时处理数万个时空位置，并根据文字或参考图决定它们应当如何变化。
